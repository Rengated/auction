# Auction Germes — онлайн-аукцион автомобилей

Платформа живых торгов: покупатели делают ставки в реальном времени, у лота есть резерв и шаг ставки, антиснайпинг продлевает финал, после победы менеджер сопровождает сделку (комиссия 1.5%). Дизайн — система «Concours» из `design-reference/`.

## Состав монорепо

| Пакет | Что это | Порт (dev) |
|---|---|---|
| `apps/api` | NestJS: auth (Яндекс ID), движок торгов, WebSocket, admin-API, Web Push | 3000 |
| `apps/web` | React+TS клиент покупателя — один адаптивный app (≤960px мобильная раскладка, шире — веб), PWA | 5173 |
| `apps/admin` | React+TS админка менеджера (desktop-only) | 5174 |
| `packages/shared` | Типы домена, DTO, имена WS-событий, хелперы — общий контракт api/web/admin | — |

Инфраструктура: PostgreSQL (Prisma), Redis (BullMQ-джобы + socket.io-adapter), MinIO (фото лотов, S3 API).

## Быстрый старт

```bash
cp .env.example .env            # при необходимости впишите ключи Яндекс OAuth / VAPID
docker compose up -d            # postgres :5433, redis :6379, minio :9000
pnpm install
pnpm db:migrate                 # миграции Prisma
pnpm db:seed                    # демо-лоты, пользователи, настройки
pnpm dev                        # api + web + admin параллельно
```

- Клиент: http://localhost:5173 · Админка: http://localhost:5174
- Без ключей Яндекса работает **dev-вход** (`AUTH_DEV_FAKE=1`): кнопка «Войти через Яндекс ID» откроет страницу выбора сид-пользователя. Менеджер — `dev-manager`, покупатели — `dev-1…8`, без контактов — `dev-nocontacts`.
- `pnpm db:reset` — полный сброс БД с пересевом (живые лоты получают свежие таймеры).

## Тесты

```bash
pnpm --filter @hermes/api test   # 11 интеграционных тестов движка (нужны docker-сервисы)
pnpm typecheck                   # tsc по всем пакетам
```

Тесты покрывают инварианты движка: конкурентные ставки (`SELECT … FOR UPDATE`), антиснайпинг, закрытие с/без резерва, страховочный поллер, идемпотентность `clientBidId`, запрет самоперебития, шторм ставок, откат отклонённой ставки.

## Архитектура движка торгов

- **Ставка** (`POST /lots/:id/bids`) — одна транзакция: row-lock лота → валидации → INSERT ставки → UPDATE цены/резерва/антиснайпинг-продление. Конкурент получает `BID_TOO_LOW` с актуальным минимумом. Ретраи идемпотентны по `clientBidId`.
- **Жизненный цикл** — BullMQ delayed-джобы `open-/close-/ending-{lotId}` + страховочный cron каждые 30 с (самовосстановление после рестартов). Закрытие перепроверяет `ends_at` под локом. Продажа → сделка со снимком комиссии.
- **Время** — сервер шлёт абсолютные `endsAt` + `serverNow`; клиент держит offset и тикает сам.
- **Real-time** — socket.io + Redis adapter; комнаты `lot:{id}`, `catalog`, `user:{id}`, `admin`. События патчат кэш TanStack Query. Имена в публичной ленте маскируются («Участник 77»), контакты видит только менеджер.
- **Push** — Web Push (VAPID): «перебили», «выиграли», «старт по избранному», «скоро закроется»; тогглы — в параметрах админки. Ключи: `npx web-push generate-vapid-keys`.

## Роли и доступ

`buyer` — каталог/ставки (для участия нужны заполненные контакты); `manager`/`admin` — админка. Сессия: access JWT 15 мин + refresh 30 дней с ротацией, оба в httpOnly cookie.
